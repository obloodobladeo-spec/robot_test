# UART 명령이 적용되지 않는 현상 확인

## 원인과 조치

- 보드 코드가 현재 빌드한 수신·명령 해석·시간 초과 정지 펌웨어와 달랐습니다. 보드에서 읽은 코드 앞부분 전체가 2026-10-22 송신 전용 시험의 ELF 코드와 일치했습니다.
- 해당 이전 ELF의 변수 배치를 이용해 차체 명령을 0으로 만들고 양쪽 듀티·CCR이 0인 것을 확인했습니다.
- Arduino 시리얼 모니터가 COM11을 점유하고 있어 이전 사용자 지시에 따라 해당 `serial-monitor.exe`만 종료했습니다.
- 기존 학습 소스는 수정하지 않고 최신 `encoder_basic.elf`를 다운로드·검증·리셋했습니다. 새 플래시 코드·초기 데이터와 ELF 일치도 다시 확인했습니다.

## 수신 확인

- `V=0 W=0\n` 전송 후 수신 head·tail이 모두 0에서 8로 이동했고, `last_command_tick`이 0에서 33794로 갱신됐습니다. 수신 상태 HAL_OK, overflow=0, 완성 줄 처리가 끝난 ready=0을 확인했습니다.
- `V=999 W=0\n` 전송 후 head·tail은 18로 이동했지만 `last_command_tick`은 33794 그대로였습니다. 범위 초과 명령이 거부됐습니다.
- 이후 COM11·115200에서 `V=50 W=0\n`을 100ms 간격으로 5초 동안 전송했습니다. 목표 속도 50mm/s 적용과 모터 PWM 출력을 확인했습니다.
- 마지막 주행 표본의 실제 속도는 왼쪽 46.26mm/s·오른쪽 47.46mm/s, 듀티 6.90%·6.51%, CCR 289·273이었습니다. 5초 시험이므로 충분한 정상상태 수렴까지 확인한 결과는 아닙니다.

## 시간 초과 정지

- 마지막 명령 기준 약 288ms인 관측 표본에서는 목표 50과 PWM 출력이 유지됐습니다.
- 약 691ms인 관측 표본에서는 차체 명령·양쪽 목표·CCR이 0이었고, 관성에 따른 측정 속도는 약 14mm/s 남았습니다.
- 약 1069ms인 관측 표본에서는 실제 속도도 모두 0이었습니다.
- SWD 순차 읽기이므로 정확한 정지 처리 시점을 계측한 것은 아닙니다. 코드의 500ms 제한과 다음 100ms 제어 주기 처리에 따라 시간 초과 정지가 발생한 것을 확인했습니다.
- 종료 시 명시적인 정지 명령도 보내고 양쪽 속도·듀티·CCR 0을 확인했습니다. COM11을 닫았고 MCU는 계속 실행 중입니다.
- 원시 파일의 `serial` 4줄은 수신 큐 앞부분에서 읽은 정지 상태 출력입니다. 주행 전체의 UART 출력 모니터링으로 해석하지 않습니다.

## 실행할 때

- 새 코드를 빌드한 뒤에는 반드시 해당 프로젝트 ELF를 보드에 다운로드해야 합니다. 빌드나 F8 재개만으로 플래시가 바뀌지는 않습니다.
- Arduino 시리얼 모니터는 COM11·115200, 줄바꿈은 Newline 또는 Both NL & CR을 사용합니다.
- 명령을 한 번만 보내면 500ms 뒤 목표가 0으로 돌아갑니다. 연속 주행은 500ms보다 짧은 간격으로 정상 명령을 반복 전송해야 합니다.
