# 가속도 제한 디버깅: 바퀴를 띄운 상태

- 사용자 확인: 바퀴를 띄운 상태에서 측정 시간을 늘렸습니다.
- 조건: Kp=0.1, Ki=0.1, 적용 목표 변화율 제한 10mm/s², 제어 간격 100ms.
- 목표 +50과 -50mm/s를 각각 20초 적용했습니다.
- 보드 플래시의 실행 코드와 초기 데이터가 현재 ELF와 일치하는 것을 먼저 확인했습니다. 이번 작업에서 펌웨어 소스 수정이나 보드 업로드는 하지 않았습니다.
- 각 시험 후 목표·적용 목표·실제 속도·적분·듀티·CCR이 모두 0인 것을 확인했습니다.

## 적용 목표 변화

| 요청 목표 | 최초 0이 아닌 적용 목표 관측 | 적용 목표가 요청 목표에 도달한 시각 |
| --- | --- | --- |
| +50 | 명령 시작 후 약 0.53초 | 약 5.47초 |
| -50 | 명령 시작 후 약 0.51초 | 약 5.36초 |

각 시험은 이전 방향과 반대로 시작했습니다. 방향 전환 전 정지 확인과 다음 제어 주기 대기, SWD 명령·조회 지연이 포함됩니다. 목표가 바뀌기 시작한 뒤 약 5초 동안 ±50까지 변했으며, 10mm/s² 제한과 일치하는 흐름입니다.

요청 목표는 처음부터 ±50이지만, 적용 목표는 서서히 변합니다. 실제 속도는 적용 목표보다 늦게 따라왔습니다. 낮은 듀티 구간에서는 적용 목표가 증가하는 동안에도 실제 속도가 0인 표본이 관측됐습니다.

## 발견한 표시 문제

`Motor_Stop()`은 목표·적용 목표·적분·듀티를 0으로 만들지만 `speed_error`를 다시 계산하지 않습니다. `Motor_Update()`도 정지 분기에서 반환하므로 실제 속도가 0이 된 후에도 이전 오차가 표시됩니다. 최종 PWM·CCR은 0이며, 이 표시값 때문에 출력이 계속 나간 것은 아닙니다.

정지 함수에서 적용 목표를 0으로 만든 뒤 다음을 추가하면 현재 측정 속도에 맞는 오차가 표시됩니다.

```c
motor->state.speed_error = -motor->state.speed_mm_s;
```

방향 전환 대기 분기에서도 적용 목표를 0으로 만든 직후 같은 갱신을 하면 관측값이 일관됩니다. 이번 디버깅에서는 학습 소스를 직접 수정하지 않았습니다.
