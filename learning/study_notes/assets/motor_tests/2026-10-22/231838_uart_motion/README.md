# UART 수신·모터 제어 장시간 비교

## 조건과 실행

- 사용자 요청에 따라 각 조건을 **40초씩**, 총 8개 조건에서 실행했습니다. 명령 적용 시간은 합계 320초이며 정지·설정·복구를 포함한 UART 기록은 약 370초입니다.
- 바퀴 공중 조건은 앞선 사용자 확인을 기준으로 했습니다. 실제 바닥 주행 정확도를 검증한 시험은 아닙니다.
- Kp=0.1 유지, 기본 Ki=0.1에서 직진 ±50·±100mm/s와 회전 ±0.3rad/s, 이후 Ki=0.2·0.3에서 직진 +50mm/s를 비교했습니다.
- 가속도 제한 100mm/s², 듀티 상한 50%, 윤거 설정 230mm를 유지했습니다. 차체 축소 후 실측 윤거는 별도 확인되지 않았습니다.
- 보드 플래시의 코드·초기 데이터와 현재 ELF 일치, Motor·Robot 구조체 배치, RAM 이득 변경 후 읽기를 확인했습니다. C 파일 수정·다운로드는 하지 않았습니다.
- COM11 점유가 남아 있어 사용자 지시에 따라 Arduino의 `serial-monitor.exe` 프로세스만 종료했습니다. Arduino IDE 전체를 종료하지 않았습니다.
- 115200·8N1로 UART를 수신하면서 SWD HOTPLUG로 실제 속도·구간 이동량·추정 위치·듀티·CCR·송신 버퍼와 상태를 읽었습니다. 시험 사이마다 차체 명령을 0으로 만들고 양쪽 모터 정지를 확인했습니다.

## 마지막 10초 속도 결과

단위 mm/s, 평균 ± 표준편차입니다. ±는 최대·최소 범위가 아닙니다. SWD 관측 표본 기준이며 모든 100ms 제어 구간을 연속 수집한 것은 아닙니다.

| 명령 | Ki | 왼쪽 속도 | 오른쪽 속도 |
|---|---|---|---|
| 전진 +50 | 0.1 | 49.91 ± 0.69 | 50.20 ± 0.92 |
| 후진 -50 | 0.1 | -49.90 ± 0.88 | -50.10 ± 1.03 |
| 전진 +100 | 0.1 | 100.00 ± 0.85 | 99.74 ± 0.69 |
| 후진 -100 | 0.1 | -99.81 ± 0.87 | -100.19 ± 0.70 |
| 회전 +0.3rad/s | 0.1 | -34.56 ± 0.77 | 34.52 ± 0.83 |
| 회전 -0.3rad/s | 0.1 | 34.29 ± 0.97 | -34.52 ± 0.99 |
| 전진 +50 | 0.2 | 49.68 ± 0.80 | 49.87 ± 0.74 |
| 전진 +50 | 0.3 | 50.25 ± 0.75 | 49.88 ± 0.73 |

각 시험의 최대·최소 속도도 원시 JSON에 저장했습니다.

## 출발 응답

| Ki | 전진 50mm/s에서 왼쪽 / 오른쪽 90% 도달 관측 |
|---|---|
| 0.1 | 4.83 / 4.44초 |
| 0.2 | 3.08 / 3.08초 |
| 0.3 | 2.33 / 1.92초 |

- 목표 방향 속도가 목표 크기의 90% 이상인 표본이 3회 연속 관측된 구간의 첫 시각입니다. 완전한 정착 시간과 다릅니다.
- 이번 공중 시험에서는 Ki 증가가 초기 응답을 빠르게 했습니다. Ki=0.3의 후반 변동도 작았지만 각 조건 1회·고정 순서 시험이므로 전체 부하 조건의 최적 이득으로 확정하지 않았습니다.
- 마지막 10초 평균 듀티는 기본 Ki 직진 +50에서 왼쪽 7.63%·오른쪽 7.36%, +100에서 13.16%·12.69%였습니다. 실제 CCR도 함께 읽었으며 평균은 각각 약 320·308, 553·532입니다.

## UART 실제 수신 검증

- 총 382개 수신 조각/줄을 저장했습니다. 포트 연결 직후 2개는 `X=0 Y=0\r\n`, `L=0L=0 R=0  X=0 Y=0\r\n` 형태로 완전한 행 형식과 맞지 않았습니다. 초기 잔여 데이터·행 경계 동기화 문제 가능성이 있으나 정확한 원인은 계측하지 않았습니다.
- 초기 2초를 제외한 수신 행은 모두 기대 형식에 맞았습니다. 이후 도착 간격은 평균 약 0.999초, 최소 약 0.984초, 최대 약 1.016초였습니다. PC 수신 시각 기준으로 실제 UART 선의 비트 간격 측정은 아닙니다.
- 관측한 송신 버퍼 815개 모두 시간상 가까운 실제 수신 행과 일치했습니다. UART 연결 예외는 없었고 관측한 송신 요청 상태는 모두 HAL_OK였습니다.
- busy는 읽은 표본에서 모두 0이었습니다. 수 ms의 송신 구간을 잡지 못한 것이므로 busy가 1이 되지 않는다고 해석하지 않습니다.
- 정지·직진·후진·양방향 회전 중에도 수신이 지속됐습니다. UART 오류나 장시간 busy 고착으로 송신이 멈추는 현상은 이번 기록에서 관측되지 않았습니다.

## 구간 이동량과 위치

- 기본 Ki의 +50 직진에서 구간 이동 거리 평균은 약 5.003mm, +100에서는 약 9.987mm였습니다.
- 회전 +0.3/-0.3rad/s에서 구간 회전각 평균은 각각 +0.030038/-0.029944rad였습니다.
- 제자리 회전 40초 동안 누적 yaw가 ±약 11.4rad까지 바뀌었습니다. 현재 yaw는 누적각이며 ±π로 제한하지 않으므로 정상적인 표현입니다.
- 누적 x·y는 시작 방향과 좌우 엔코더 차이에 따라 변했습니다. 위치는 초기화하지 않았으며 실제 차체 이동량 검증은 아닙니다.

## 종료

- 마지막에 차체 속도 명령, 양쪽 목표·실제 속도·구간 이동량·적분·듀티·CCR, 차체 구간 이동량·회전각 모두 0을 확인했습니다.
- 양쪽 Kp=0.1·Ki=0.1로 복구하고 읽기 확인했습니다. 누적 위치는 유지했습니다.
- 마지막 UART 행은 `L=0 R=0  X=3942 Y=-27`이 반복됐습니다.
- COM11 연결을 정상적으로 닫았습니다. MCU 펌웨어는 계속 실행 중이며 Arduino IDE에서 시리얼 모니터를 다시 열 수 있습니다.
- 원시 기록: `measurements.json`. 수신 검증 집계: `validation.json`.
