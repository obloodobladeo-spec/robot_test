# 2026-10-18 공부 기록

## 학습 주제

- 로봇 바퀴 속도 제어에서 P·I항의 의미와 코드 실행 순서 복습
- 엔코더 측정 → 속도 → 오차 → 듀티 → CCR의 연결 이해
- Kp·Ki 크기에 따른 계산 결과 비교

## 핵심 개념

### 현재 실습 기준

- 프로젝트: STM32CubeIDE/workspace_2.2.0/encoder_basic
- 모터1 PWM: PA8 / TIM1_CH1, DIR: PC0, 양의 속도 시험 방향은 HIGH
- 엔코더: PA0·PA1 / TIM2, Encoder TI12 ×4
- 바퀴 지름 110mm, 둘레 약 345.6mm, 실측 2465.2count/바퀴
- TIM1 클럭 84MHz, PSC 0, ARR 4199 → 20kHz PWM
- CNT는 하드웨어가 계속 세며, 메인에서 100ms마다 측정·제어 계산
- CCR = (ARR+1) × 듀티 / 100. ARR은 4199, 한 주기 count 수는 4200
- 같은 CCR을 매 while에 써도 CNT나 PWM 주기가 다시 시작되지 않음

### 사용한 제어식

~~~text
e[k] = r[k] - y[k]
P[k] = Kp * e[k]
I_candidate[k] = I[k-1] + Ki * e[k] * dt
u[k] = P[k] + I[k]
~~~

| 기호 | 코드 | 의미 / 단위 |
| --- | --- | --- |
| r | motor1_target_speed | 목표 속도, mm/s |
| y | motor1_speed | 엔코더 기반 바퀴 속도, mm/s |
| e | motor1_speed_error | 제어 오차, mm/s |
| Kp | motor1_kp | 오차에 대한 비례 이득, %/(mm/s) |
| Ki | motor1_ki | 적분 이득, %/[(mm/s)·s] |
| dt | dt_s | 실제 구간 시간, 초 |
| P | p_output | 현재 오차에 비례한 출력, % |
| I | motor1_i_output | 이전 구간부터 누적한 출력, % |
| u | M1_duty_percent | 출력 제한을 적용할 듀티 명령, % |

출처: [Microchip 공식 PI 제어 문서](https://onlinedocs.microchip.com/oxy/GUID-69278EBA-9F00-4CEE-8103-2998236856BD-en-US-2/GUID-68C13886-A5D4-4274-9410-D1AE3D79CFF9.html).
연속시간 PI 식을 코드의 구간별 누적 형태로 표현했다. 적분 후보는 조건부 적분 검사 후 저장하며 최종 출력은 별도로 제한해야 한다.

### P항을 이해하며 확인한 내용

- Kp는 모터 사양이나 엔코더 측정값이 아니라 사용자가 조정하는 제어 이득이다.
- Kp=0.1이면 속도 오차 1mm/s당 듀티 0.1%를 계산한다.
- 목표 100, 측정 0이면 P 출력 10%. 다음 측정이 40이면 P 출력 6%로 덮어쓴다.
- 기존 10%에 6%를 더하는 구조가 아니다.
- 출력을 줄여 느려지면 다음 구간에서 오차가 커져 P 출력도 다시 증가한다.
- 직접 출력 방식의 P 제어는 회전을 유지할 출력까지 오차로 만들어야 하므로 정상상태 오차가 남을 수 있다.
- P의 목적은 오차를 의도적으로 남기는 것이 아니라 현재 오차에 비례해 반응하는 것이다.
- 모든 제어 대상에서 P만 쓰면 반드시 정상상태 오차가 남는다고 일반화하지 않는다.

### I항의 의미

- Ki는 남아 있는 오차를 얼마나 빠르게 적분 출력에 누적할지 정한다.
- 오차가 양수면 I 출력 증가, 음수면 감소, 0이면 기존 I 출력 유지.
- 목표에 도달해 P 출력이 거의 0이어도 I 출력은 유지 출력을 제공할 수 있다.
- Ki=0, 초기 I=0이면 새 적분 출력은 쌓이지 않아 사실상 P 제어로 동작한다.
- 출력이 포화된 상태에서 그 방향으로 적분을 더 쌓지 않도록 조건부 적분 제한을 사용한다.

### 코드 실행 순서

~~~text
초기화 → CCR 0·DIR HIGH → CNT 0·엔코더 시작
→ 이전 count·시간 저장 → PWM 시작
→ while 앞부분에서 현재 듀티를 CCR에 적용
→ 100ms 경과 시 구간 count·회전량·거리·실제 속도·RPM 계산
→ 목표와의 오차 → P 출력 → I 후보 → 적분 저장 여부 판단
→ P+I를 듀티에 저장·출력 제한 → 측정 기준 갱신
→ 다음 while에서 새 듀티를 CCR에 적용
~~~

### Ki=0.1 설명용 계산

전제: 목표 100mm/s, Kp=0.1, Ki=0.1, dt=0.1초, 초기 I=0, 상한 20% 적용.
아래 속도는 계산을 설명하기 위해 주어진 예시이며 모터 응답 예측값이 아니다.

| 구간 | 측정 속도 | 오차 | P 출력 | 이번 I 증가 | 저장 I | 최종 듀티 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| 첫 구간 | 0 | 100 | 10% | 1% | 1% | 11% |
| 다음 구간 | 40 | 60 | 6% | 0.6% | 1.6% | 7.6% |
| 다음 구간 | 60 | 40 | 4% | 0.4% | 2% | 6% |

P가 줄어드는 동안 I가 누적될 수 있다. 실제 다음 속도는 모터·하중·출력에 의해 결정되므로 위 숫자를 실제 시간 응답으로 해석하지 않는다.
오차 60, dt 0.1초일 때 Ki를 0.05/0.1/0.2로 바꾸면 이번 적분 증가량은 각각 0.3/0.6/1.2%다.
같은 오차 60에서 Kp를 0.05/0.1/0.2로 바꾸면 P 출력은 각각 3/6/12%다.
Kp·Ki가 커진다고 최종 속도가 비례해 증가하는 것은 아니며, 너무 크게 설정하면 진동·초과 응답이나 출력 포화가 생길 수 있다.

### 이득 조정 전 저장 코드 상태: 2026-10-18 최초 검토

- 초기 듀티 0, 목표 속도 0, Kp=0.1, Ki=0, 초기 I=0.
- 목표를 바꾸지 않으면 정지 상태다. Ki=0은 P부터 복습하기 위한 설정으로 볼 수 있다.
- PWM 앞쪽 20% 상한이 주석 처리되어 있다.
- 최종 상한 조건 안에서 M1_duty_percent = M1_duty_percent로 자기 대입하여 출력 제한이 작동하지 않는다.
- 20% 상한 시험을 유지하려면 그 대입을 M1_duty_percent = 20.0f로 고쳐야 한다. 적분 제한의 20% 기준과도 일치시켜야 한다.
- 현재 count 차분은 signed·unsigned 혼합이다. 하드웨어 CNT와 이전 CNT를 uint32_t로 읽어 차분 후 int32_t로 해석하도록 명시하면 의도가 분명하다.
- 이번 기록 작업에서는 펌웨어 수정·빌드·업로드·실제 모터 측정을 하지 않았다.

## 의문과 어려웠던 점

- while을 다시 돌면 듀티가 초기값으로 돌아가는가? → 아니며, if 안에서 덮어쓴 값이 다음 반복에도 유지된다.
- 10%에서 속도 40이면 왜 6%로 줄이는가? → P는 이전 출력의 부족분을 누적하지 않고 현재 오차만으로 출력을 새로 계산한다.
- 줄여서 느려지면 오차가 커지지 않는가? → 맞다. 다음 구간에서 P 출력이 다시 커져 균형 또는 진동이 생길 수 있다.
- Kp를 크게 하면 목표 속도 오차가 무조건 없어지는가? → 아니다. 민감도·진동·포화 등을 함께 고려해야 한다.
- I가 남는다는 것은 현재 오차가 남는다는 뜻인가? → 아니다. 과거 오차를 누적한 출력이 저장돼 있다는 뜻이다.

## 추가 실습: 이득 비교와 휠·허브 영향 확인

### 사용자 관찰과 해석

기존 바퀴는 지름 110mm이며 휠 허브를 3D 프린터로 직접 제작했다. 사용자가 결합 상태가 좋지 않다고 확인했다.
현재 모터가 차체·바퀴 조건에 비해 힘이 충분하지 않다는 사용자 관찰도 기록한다. 정격·스톨 토크, 전류 및 최종 하중에서의 토크 여유를 실측한 것은 아니다.

### 실제 시험 결과

바퀴를 띄운 상태에서 목표 100mm/s, 제어 간격 100ms, 출력 상한 20%를 유지하며 비교했다.
아래 이득 비교값은 각 시험 마지막 약 7초의 조회 결과이며 동일한 날의 한정된 조건이다.

| Kp | Ki | 속도 범위 | 해석 |
| ---: | ---: | --- | --- |
| 0.1 | 0.1 | 약 82.71~112.15mm/s | 최초 기준의 주기 변동 재현 |
| 0.1 | 0.05 | 약 82.71~112.15mm/s | Ki만 줄여도 큰 개선 없음 |
| 0.05 | 0.1 | 약 75.70~116.36mm/s | Kp를 줄인 조건은 오히려 변동 증가 |
| 0.15 | 0.1 | 약 84.11~110.75mm/s | 일부 개선 |
| 0.2 | 0.1 | 재검증 약 88.32~109.35mm/s | 시험 범위 중 변동이 작아 현재 시작값으로 선택 |

고정 듀티 14.4%·CCR1=604에서도 약 72.90~126.17mm/s 변동이 남았다. 따라서 PI 이득 설정만으로 원인을 설명할 수 없다.

| 같은 기존 모터의 상태 | 고정 CCR1=604 속도 범위 | PI: Kp=0.2·Ki=0.1 속도 범위 | PI 조회 평균 |
| --- | --- | --- | --- |
| 기존 휠 최초 장착 | 약 72.90~126.17mm/s | 약 88.32~109.35mm/s | 약 100.09mm/s |
| 휠 제거 | 약 123.37~124.77mm/s | 약 96.73~102.34mm/s | 약 99.81mm/s |
| 다른 휠 장착 | 약 121.97~123.37mm/s | 약 96.73~102.34mm/s | 약 99.86mm/s |
| 기존 휠 재장착 | 약 113.56~123.37mm/s | 약 95.33~102.34mm/s | 약 99.86mm/s |

고정 출력 시험은 각 약 18초, PI는 약 22~24초 진행했다. 표의 mm/s는 기존 둘레 345.6mm로 계산한 바퀴 기준 환산값이며 실제 차체 속도가 아니다. 휠 제거 때도 같은 환산식을 유지했다. 교체 휠의 지름은 미확인이다.
다른 모터로 교체했던 별도 시험은 PI 평균 약 99.84mm/s, 범위 약 96.73~102.34mm/s였다. 이후에는 기존 모터로 되돌려 휠 제거·다른 휠·기존 휠 재장착을 비교했다.

결론: 휠·허브 장착과 하중 영향이 주요 원인 후보다. 기존 휠 재장착 때 최초 큰 변동이 재현되지 않아 휠 자체 불량이나 모터 고장을 확정하지 않는다.
사용자의 3D 프린트 허브 결합 불량 관찰과 함께 해석하며, 개별 원인은 향후 편심·유격·간섭을 확인해야 한다.
상세 구성과 측정 한계는 hardware/README.md의 휠·허브 검사 절에 기록했다.

### 현재 코드 상태 갱신

- 앞의 이득 조정 전 검토 이후 상한 자기 대입 오류가 수정됐다. 현재 앞쪽·최종 듀티 제한 모두 20%를 적용한다.
- 이득 비교를 위해 Kp·Ki를 RAM의 일반 float 변수로 변경했다. 현재 저장값은 Kp=0.2, Ki=0.1이다.
- 초기 목표·듀티·적분 출력은 0이다. 이득 조정 준비와 선택값 반영 때 빌드·업로드 및 다운로드 검증을 수행했다.
- 이후 모터·휠 비교는 소스 수정·재업로드 없이 RAM의 목표·이득을 변경하고 실제 CCR1을 읽었다.
- 목표 0 → 50 → 100 → 50 → 0 변경 시험에서 가속·감속과 최종 정지 동작을 확인했다. 각 주행 약 8초로, 모든 구간의 완전한 수렴을 검증한 것은 아니다.
- 모든 시험 후 목표·측정 속도·듀티·I 출력·CCR1=0을 읽어 정지 확인. 오늘 문서 갱신 시에는 모터를 구동하지 않았다.

### 다음 학습: 정·역방향 목표 속도 처리

- 현재는 DIR HIGH에서 양의 측정 속도를 사용하고 목표가 0 이하이면 정지하므로 음의 목표 제어는 아직 구현되지 않았다.
- 목표의 부호로 원하는 방향을, 절댓값으로 원하는 속력 크기를 구분한다.
- 방향별 PI는 해당 명령 방향 기준으로 속도를 환산해 계산한다. 측정 속도에 무조건 절댓값을 쓰면 반대 방향 움직임을 숨길 수 있다.
- 반대 방향 명령에서는 PWM 0 → 실제 감속·정지 확인 → I 초기화 → DIR 변경 → 출력 재개 순서를 먼저 설계한다.
- 단순히 목표 부호가 바뀌었다고 구동 중 DIR을 즉시 바꾸지 않는다.
- 다음 코드는 기존 엔코더·PI 측정을 유지하면서 위 방향 전환 절차를 연결한다. 양쪽 모터·바닥 주행은 이후 단계다.
