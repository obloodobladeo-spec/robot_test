### CubeMX 설정

- TIM1: 내부 타이머 클럭 84MHz, PSC=0, ARR=4199, PWM 20kHz
- TIM1 CH1·CH2: PWM mode 1, Pulse=0, Polarity High, Fast Mode Disable, Output Compare Preload Enable
- TIM1 Auto-reload preload Enable
- TIM2: Encoder TI1 and TI2, PSC=0, ARR=4294967295, 입력 필터 CH1/CH2 모두 4
- TIM3: Encoder TI1 and TI2, PSC=0, ARR=65535, 입력 필터 CH1/CH2 모두 4
- 엔코더 입력: Polarity Rising, Direct TI, DIV1, Auto-reload preload Disable
- 엔코더 인터럽트는 사용하지 않음. 하드웨어가 카운트하고 메인에서 읽음
- DIR: Output Push Pull, No pull, Low speed

## 핵심 개념

### 카운터 원본과 부호 있는 이동량

TIM2와 TIM3의 하드웨어 CNT는 모두 부호 없는 값입니다. TIM2 값을 int32_t로 변환할 때 현재 ARM GCC 환경에서는 32비트 부호를 해석하므로 4294967295가 -1로 보입니다. TIM3의 65535를 int32_t로 변환하면 +65535이므로 같은 코드만 복사하면 안 됩니다.

모터 2에서는 현재 CNT와 이전 CNT의 차이를 구한 뒤 16비트 경계 통과를 보정합니다.

```c
motor2_dt_cnt = (int32_t)motor2_current_cnt - (int32_t)M2_previous_cnt;
if (motor2_dt_cnt > 32767)
{
    motor2_dt_cnt -= 65536;
}
else if (motor2_dt_cnt < -32768)
{
    motor2_dt_cnt += 65536;
}
```

- 65530 → 4: 단순 차이 -65526, 보정 후 +10
- 4 → 65530: 단순 차이 +65526, 보정 후 -10
- 0에서 역방향으로 움직여 65535가 되는 것은 정상
- motor2_count는 원시 CNT이며, 방향 판단에는 motor2_dt_cnt와 motor2_speed를 사용
- 보정은 한 측정 구간의 실제 이동량이 ±32768카운트 미만이라는 조건에 의존

### 측정 주기와 엔코더 카운트 주기는 다름

엔코더 카운트는 신호 에지에 따라 하드웨어에서 계속 변합니다. 100ms는 카운터가 세는 간격이 아니라 메인이 속도 계산을 수행하는 기준 간격입니다. 실제 경과 시간 sample_dt_ms를 사용하므로 항상 정확히 100ms라고 가정하지 않습니다.

두 모터는 같은 측정 시간 간격을 사용하지만 이전 CNT는 각각 M1_previous_cnt, M2_previous_cnt로 따로 보관합니다. 현재 속도와 거리는 바퀴 회전으로 환산한 값이며 타이어가 미끄러지면 실제 차체 이동과 다를 수 있습니다.

### PI 속도 제어

```text
e(t) = r(t) - y(t)
u(t) = Kp × e(t) + Ki × ∫ e(t) dt
```

- e: 제어 오차, r: 목표 속도, y: 측정 속도 (mm/s)
- 출력 u: 듀티 %, Kp 단위: %/(mm/s), Ki 단위: %/((mm/s)·s)
- 코드의 적분 후보: 이전 적분 출력 + Ki × 오차 × 실제 경과 시간(초)
- Kp는 현재 오차에 즉시 반응하고 Ki는 남는 오차를 시간에 따라 누적
- P 출력은 기존 듀티에 더하는 증가량이 아니라 매 주기 다시 계산하는 출력 성분
- motor1_i_output과 motor2_i_output은 각 모터의 이력을 저장하므로 공유하지 않음

사용한 연속 PI 식의 출처: [Microchip 공식 PI 제어 설명](https://onlinedocs.microchip.com/oxy/GUID-69278EBA-9F00-4CEE-8103-2998236856BD-en-US-2/GUID-68C13886-A5D4-4274-9410-D1AE3D79CFF9.html). 코드는 실제 측정 간격을 곱해 적분을 누적하는 이산 구현입니다.

현재 두 모터 모두 Kp=0.2, Ki=0.1이며 출력은 0~20%입니다. 모터 2의 최적 이득으로 검증된 값은 아닙니다.

예: 목표 100, 실제 0, dt=0.1초, 이전 적분 출력 0이면 P=20%, 적분 후보=1%입니다. 합계 21%가 상한을 넘고 오차도 양수이므로 적분 후보는 저장하지 않고 출력은 20%로 제한합니다. 마지막 0.1은 Ki가 아니라 측정 시간(초)입니다.

### 부호와 방향 전환

최종 사용자 확인 기준은 두 모터 모두 DIR HIGH=전진=양수 속도입니다. 모터 2가 HIGH에서 후진·음수라는 중간 진술은 최종 확인으로 정정했습니다.

- 양수 목표: HIGH, 방향 상태 +1
- 음수 목표: LOW, 방향 상태 -1
- 목표 0: 듀티·적분 출력·정지 확인 횟수를 0으로 초기화
- 현재 방향과 요청 방향이 다르면 먼저 듀티와 적분 출력을 0으로 설정
- 100ms 측정에서 엔코더 순변화량이 3회 연속 0이면 DIR 변경
- 방향 변경 다음 제어 주기부터 PI 제어
- control_error = direction × speed_error로 전진·후진 모두 속도 부족 시 출력을 증가시킴

3회 연속 순변화량 0은 정지 판단 기준이며 물리적인 완전 정지를 보증하는 별도 센서는 아닙니다.

### 변수 선언

현재 엔코더 측정과 PI 상태는 메인에서만 읽고 쓰므로 volatile을 미리 추가하지 않습니다. 인터럽트와 공유하는 등 실제 필요가 생길 때 이유를 설명하고 추가합니다.

## 코드 실행 순서

```text
HAL_Init → SystemClock_Config → GPIO/TIM 초기화
→ CCR1·CCR2=0 → 두 엔코더 CNT=0 → DIR HIGH
→ 두 엔코더 시작 → 이전 CNT와 tick 저장 → 두 PWM 시작
→ while 반복
  → 현재 듀티를 CCR1·CCR2에 반영
  → 100ms 이상 경과하면 실제 dt 계산
  → 두 엔코더 변화량·속도·RPM 계산
  → 모터 1 정지/방향/PI 계산
  → 모터 2 정지/방향/PI 계산
  → previous_tick과 두 이전 CNT를 마지막에 갱신
```

previous_tick을 시간 차이 계산 전에 now로 덮어쓰면 dt가 0이 됩니다. 제어 코드 추가 위치는 tick 저장 코드 앞입니다. 새 듀티는 다음 while 반복에서 CCR에 기록됩니다.

PWM 비교값은 (ARR+1) × 듀티 / 100을 정수로 변환한 값입니다. ARR=4199이므로 20%는 CCR=840입니다.
