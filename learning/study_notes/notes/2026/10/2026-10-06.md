# 2026-10-06 STM32 PWM·타이머·엔코더 기초와 실제 모터 제어 설정

## 학습 목표

NUCLEO-F446RE, Cytron MDD10A, JGB37-520 엔코더 모터 2개를 연결하면서 사용한 기능을 실제 설정값과 함께 정리한다.

- 타이머가 무엇인지 이해한다.
- `Prescaler`, `Counter Period`, `CCR`의 관계를 이해한다.
- PWM 주파수와 듀티비가 어떻게 결정되는지 계산한다.
- MDD10A의 `PWM`과 `DIR` 역할을 구분한다.
- Hall 엔코더 A/B상의 위상 차이로 방향을 판별하는 원리를 이해한다.
- TIM2와 TIM3의 Encoder Mode 설정값이 무엇을 의미하는지 이해한다.
- 다음 단계인 카운트 변화량 기반 RPM 계산을 준비한다.

## 전체 신호 흐름

```text
STM32 TIM1 PWM + GPIO DIR
          │
          ▼
       MDD10A ──────> DC 모터 회전
                         │
                         ▼
              Hall Encoder A/B
                         │
                         ▼
             STM32 TIM2 / TIM3 CNT
```

STM32가 모터를 직접 구동하는 것은 아니다. STM32는 작은 3.3V 제어신호만 MDD10A로 보내고, 실제 모터 전류는 배터리와 MDD10A를 통해 흐른다.

## 1. GPIO와 Alternate Function

STM32 핀은 설정에 따라 여러 역할을 맡을 수 있다.

- 일반 출력 GPIO: `DIR1`, `DIR2`처럼 HIGH/LOW를 직접 출력한다.
- Alternate Function: 핀을 타이머 같은 주변장치에 연결한다.
- 입력 GPIO: 외부 신호의 HIGH/LOW를 읽는다.

현재 핀 배치는 다음과 같다.

| 기능 | MCU 핀 | Nucleo 보드 표기 | 주변장치 |
| --- | --- | --- | --- |
| Motor 1 PWM | PA8 | D7 | TIM1_CH1 |
| Motor 2 PWM | PA9 | D8 | TIM1_CH2 |
| Motor 1 DIR | PC0 | A5 | GPIO Output |
| Motor 2 DIR | PC1 | A4 | GPIO Output |
| Motor 1 Encoder A | PA0 | A0 | TIM2_CH1 |
| Motor 1 Encoder B | PA1 | A1 | TIM2_CH2 |
| Motor 2 Encoder A | PA6 | D12 | TIM3_CH1 |
| Motor 2 Encoder B | PA7 | D11 | TIM3_CH2 |

PA8을 TIM1_CH1로 설정하면 CPU가 PA8을 매번 HIGH/LOW로 바꾸지 않아도 TIM1 하드웨어가 PWM 파형을 출력한다. 엔코더 핀도 TIM2·TIM3에 연결하면 CPU 인터럽트 없이 하드웨어가 A/B 펄스를 계산한다.

## 2. 타이머의 기본 구조

STM32 타이머의 핵심 요소는 다음과 같다.

```text
Timer Clock
   │
   ▼
Prescaler(PSC)
   │
   ▼
Counter(CNT) ── 0, 1, 2, 3 ... ARR
   │
   ├─ CCR과 비교해서 PWM 생성
   └─ 외부 엔코더 신호에 따라 증가·감소
```

### 주요 용어

| 용어 | 의미 |
| --- | --- |
| Timer Clock | 타이머에 공급되는 기준 클록 |
| Prescaler, PSC | 기준 클록을 나누는 값 |
| Counter, CNT | 현재 카운터 값 |
| Auto Reload Register, ARR | 카운터가 반복되는 끝값 |
| Capture/Compare Register, CCR | PWM 전환 시점 또는 입력 캡처 값을 저장하는 레지스터 |
| Channel | 하나의 타이머가 제공하는 독립 입출력 경로 |

Prescaler의 실제 분주값은 `PSC + 1`이다. `Prescaler = 0`이면 0으로 나눈다는 뜻이 아니라 1분주, 즉 나누지 않는다는 뜻이다.

카운터는 `0`부터 `ARR`까지 세므로 한 주기의 카운트 수는 `ARR + 1`이다.

## 3. 현재 프로젝트의 클록 계산

현재 `SystemClock_Config()`의 주요 설정은 다음과 같다.

```text
HSI = 16MHz
PLLM = 16
PLLN = 336
PLLP = 4
AHB Divider = 1
APB1 Divider = 2
APB2 Divider = 1
```

시스템 클록 계산:

```text
PLL 입력 = 16MHz / 16 = 1MHz
PLL VCO  = 1MHz × 336 = 336MHz
SYSCLK   = 336MHz / 4 = 84MHz
```

현재 CPU와 AHB 클록은 84MHz이다.

| 버스 | 버스 클록 | 현재 사용하는 타이머 | 타이머 클록 |
| --- | ---: | --- | ---: |
| APB2 | 84MHz | TIM1 | 84MHz |
| APB1 | 42MHz | TIM2, TIM3 | 84MHz |

STM32F4에서는 APB Prescaler가 1보다 크면 해당 APB의 타이머 클록이 버스 클록의 2배가 된다. 따라서 APB1은 42MHz지만 TIM2와 TIM3에는 84MHz가 공급된다.

칩 자체는 더 높은 클록을 지원하지만, **현재 프로젝트에서 실제로 설정한 시스템 클록은 84MHz**이다.

## 4. PWM의 원리

PWM은 일정한 주기 안에서 HIGH인 시간의 비율을 바꾸는 방식이다.

```text
듀티 25%:  ┌──┐      ┌──┐
            │  │      │  │
────────────┘  └──────┘  └────

듀티 75%:  ┌──────┐  ┌──────┐
            │      │  │      │
────────────┘      └──┘      └
```

PWM은 배터리 전압을 선형으로 낮추는 기능이 아니다. MDD10A가 모터에 전체 배터리 전압을 빠르게 연결하고 끊으며, 모터가 평균적인 효과를 받아 속도와 토크가 변한다.

### PWM 주파수 공식

Up Counter와 edge-aligned PWM 기준:

```text
PWM 주파수 = Timer Clock / ((PSC + 1) × (ARR + 1))
```

현재 TIM1 설정:

```c
htim1.Init.Prescaler = 0;
htim1.Init.Period = 4199;
```

계산:

```text
PWM 주파수
= 84,000,000 / ((0 + 1) × (4199 + 1))
= 84,000,000 / 4200
= 20,000Hz
= 20kHz
```

MDD10A의 최대 PWM 입력 주파수가 20kHz이므로 현재 설정은 공식 상한과 일치한다.

### 듀티비와 CCR

PWM1 모드에서 현재 설정의 듀티비는 다음처럼 계산한다.

```text
Duty = CCR / (ARR + 1) × 100%
```

현재 `ARR + 1 = 4200`이므로:

| 목표 듀티 | CCR 값 |
| ---: | ---: |
| 0% | 0 |
| 10% | 420 |
| 20% | 840 |
| 50% | 2100 |
| 100% | 4200에 해당하지만 구현 시 ARR와 HAL 동작 범위를 확인 |

현재 시험 코드는 다음 계산을 사용했다.

```c
const uint32_t period_ticks = __HAL_TIM_GET_AUTORELOAD(timer) + 1U;

__HAL_TIM_SET_COMPARE(
    timer,
    TIM_CHANNEL_1,
    period_ticks * motor1_percent / 100U
);
```

### 현재 TIM1 파라미터 의미

| 설정 | 현재 값 | 의미 |
| --- | ---: | --- |
| Prescaler | 0 | 타이머 클록을 나누지 않음 |
| Counter Mode | Up | 0에서 ARR까지 증가 |
| Period, ARR | 4199 | 4200카운트마다 PWM 한 주기 |
| Clock Division | DIV1 | 내부 디지털 필터용 타이밍을 추가 분주하지 않음 |
| Repetition Counter | 0 | 매 PWM 주기마다 갱신 가능 |
| Auto Reload Preload | Enable | ARR 변경을 안전한 갱신 시점에 반영 |
| OC Mode | PWM1 | CNT와 CCR 비교로 active 구간 생성 |
| Pulse | 0 | 시작할 때 0% 듀티로 안전 정지 |
| Polarity | High | PWM active 구간이 HIGH |

## 5. MDD10A의 PWM과 DIR

현재는 Sign-Magnitude 방식으로 제어한다.

| PWM | DIR | 결과 |
| --- | --- | --- |
| LOW, 0% | 상관없음 | 정지 |
| PWM 출력 | LOW | 한 방향 회전 |
| PWM 출력 | HIGH | 반대 방향 회전 |

따라서 역할은 다음처럼 분리된다.

```text
PWM = 얼마나 빠르게 돌릴 것인가
DIR = 어느 방향으로 돌릴 것인가
```

현재 MDD10A 제어 커넥터와 STM32 연결:

```text
MDD10A GND  -> STM32 GND
MDD10A PWM2 -> PA9 / TIM1_CH2
MDD10A DIR2 -> PC1
MDD10A PWM1 -> PA8 / TIM1_CH1
MDD10A DIR1 -> PC0
```

방향을 바꿀 때는 먼저 PWM을 0%로 만들어 모터를 정지시킨 뒤 DIR을 바꾸는 편이 안전하다.

## 6. 엔코더 A/B상의 원리

Quadrature Encoder는 위상이 어긋난 두 디지털 신호 A와 B를 출력한다.

```text
한 방향:
A: ──┌────┐────┌────┐──
B: ────┌────┐────┌────┐

반대 방향:
B가 A보다 먼저 변함
```

STM32는 어느 신호가 먼저 변했는지 보고 다음처럼 판단한다.

- 한 방향: CNT 증가
- 반대 방향: CNT 감소

A와 B 선을 서로 바꾸면 카운트 방향도 반대로 바뀐다. 최종 차체 조립 후에는 **바퀴 전진을 양수**로 통일하면 된다. 모터선이나 A/B선을 바꾸거나 소프트웨어에서 부호를 반전할 수 있다.

## 7. EXTI 방식과 Timer Encoder Mode의 차이

처음 학습에서는 PA0의 A상 상승 에지마다 EXTI 인터럽트를 발생시키고 PA1의 B상 값을 읽었다.

```c
void HAL_GPIO_EXTI_Callback(uint16_t GPIO_Pin)
{
    if (GPIO_Pin == GPIO_PIN_0)
    {
        if (HAL_GPIO_ReadPin(GPIOA, GPIO_PIN_1) == GPIO_PIN_SET)
            encoder_count++;
        else
            encoder_count--;
    }
}
```

이 방식은 원리를 이해하기 쉽지만 펄스마다 CPU가 인터럽트를 처리해야 한다.

Timer Encoder Mode에서는 TIM 하드웨어가 A/B 신호를 직접 해석하고 `CNT`를 증가·감소시킨다.

| 비교 | EXTI 방식 | Timer Encoder Mode |
| --- | --- | --- |
| 방향 판별 | 콜백 코드에서 수행 | 타이머 하드웨어가 수행 |
| CPU 부하 | 펄스마다 인터럽트 | 주기적으로 CNT만 읽음 |
| 고속 펄스 | 누락 위험 증가 | 더 안정적 |
| 모터 여러 개 | 관리가 복잡해짐 | 타이머별로 분리 가능 |

Timer Encoder Mode로 전환했기 때문에 기존 PA0 EXTI 설정은 해제했다.

## 8. TIM2와 TIM3 엔코더 설정

### 핀과 타이머

| 모터 | Encoder A | Encoder B | 타이머 |
| --- | --- | --- | --- |
| Motor 1 | PA0 / TIM2_CH1 | PA1 / TIM2_CH2 | TIM2 |
| Motor 2 | PA6 / TIM3_CH1 | PA7 / TIM3_CH2 | TIM3 |

### 공통 Encoder Mode 설정

```text
Combined Channels = Encoder Mode
Encoder Mode       = TI1 and TI2
Polarity           = Rising Edge
IC Selection       = Direct
Prescaler Ratio    = No division
Input Filter       = 4
```

### `Encoder Mode TI1 and TI2`

HAL 코드에서는 다음 값이다.

```c
sConfig.EncoderMode = TIM_ENCODERMODE_TI12;
```

이 설정은 Encoder Mode 3, x4 방식이다. TI1과 TI2 양쪽 에지를 사용하고 다른 입력의 레벨로 방향을 판별한다.

엔코더 판매자가 말하는 PPR이 A상 한 주기의 개수라면 x4 해석 후 카운트 수는 4배가 된다. 그러나 판매처마다 PPR, CPR, 모터축 기준, 감속기 출력축 기준을 혼용하므로 최종 `counts_per_output_revolution`은 실제로 한 바퀴 돌려 측정해야 한다.

### `IC Selection = Direct`

```c
sConfig.IC1Selection = TIM_ICSELECTION_DIRECTTI;
sConfig.IC2Selection = TIM_ICSELECTION_DIRECTTI;
```

의미:

```text
CH1은 물리적 TI1 입력을 직접 사용
CH2는 물리적 TI2 입력을 직접 사용
```

A와 B가 각각 자신의 채널로 바로 들어오는 일반적인 엔코더 연결이다.

### `Prescaler Division Ratio = No division`

```c
sConfig.IC1Prescaler = TIM_ICPSC_DIV1;
sConfig.IC2Prescaler = TIM_ICPSC_DIV1;
```

입력 에지를 2개, 4개, 8개마다 하나씩 버리지 않고 유효한 모든 에지를 사용한다. 엔코더 해상도를 유지하기 위해 DIV1을 사용한다.

이 항목은 타이머의 `htim.Init.Prescaler`와 이름은 비슷하지만 위치와 역할이 다르다.

| 구분 | 현재 값 | 역할 |
| --- | --- | --- |
| Timer Prescaler | 0 | 타이머 기본 분주 설정 |
| Input Capture Prescaler | DIV1 | 엔코더 입력 이벤트를 건너뛰지 않음 |

### `Input Filter = 4`

```c
sConfig.IC1Filter = 4;
sConfig.IC2Filter = 4;
```

이 값은 4번 평균낸다는 뜻이 아니다. STM32F446의 `ICxF = 0100` 설정으로, `fDTS/2` 속도로 입력을 샘플링하고 같은 상태가 6회 연속 확인되어야 변화를 인정하는 디지털 필터다.

현재 `Clock Division = DIV1`이고 타이머 기준 클록이 84MHz이므로 개념적으로:

```text
필터 샘플링 주파수 = 84MHz / 2 = 42MHz
6회 확인 시간      ≈ 6 / 42MHz ≈ 0.143µs
```

매우 짧은 잡음은 거르고 정상 Hall 엔코더 펄스는 통과시키는 보수적인 시작값이다. 필터 값을 지나치게 높이면 매우 빠른 유효 펄스까지 놓칠 수 있다.

### Polarity = Rising Edge

```c
sConfig.IC1Polarity = TIM_ICPOLARITY_RISING;
sConfig.IC2Polarity = TIM_ICPOLARITY_RISING;
```

입력을 반전하지 않는 기본 극성으로 사용한다. TI1 and TI2 Encoder Mode는 A/B 상태 변화를 함께 해석하기 때문에 x4 카운팅이 가능하다.

## 9. TIM2와 TIM3의 카운터 크기

TIM2는 32비트이고 TIM3는 16비트이다.

| 타이머 | 비트 수 | Counter Period | 원시 CNT 범위 |
| --- | ---: | ---: | --- |
| TIM2 | 32비트 | 4294967295 | 0 ~ 4294967295 |
| TIM3 | 16비트 | 65535 | 0 ~ 65535 |

현재 설정:

```c
htim2.Init.Prescaler = 0;
htim2.Init.Period = 4294967295;

htim3.Init.Prescaler = 0;
htim3.Init.Period = 65535;
```

`Counter Mode = Up`으로 초기화했더라도 Encoder Mode가 활성화되면 실제 카운트 방향은 A/B상의 순서에 따라 하드웨어가 증가 또는 감소로 결정한다.

역방향에서 0 아래로 내려가면 원시 레지스터는 최대값으로 돌아간다. 디버거에서 이를 부호 있는 값으로 보기 위해 다음처럼 형변환했다.

```c
volatile int32_t motor1_count = 0;
volatile int16_t motor2_count = 0;

motor1_count = (int32_t)__HAL_TIM_GET_COUNTER(&htim2);
motor2_count = (int16_t)__HAL_TIM_GET_COUNTER(&htim3);
```

TIM3을 `int16_t`로 보면 표시 범위는 -32768~32767이다. 장시간 누적 위치에는 좁지만 짧은 주기의 RPM 변화량 계산에는 충분하다.

## 10. 엔코더 시작 코드

CubeMX의 초기화 함수는 설정만 하고 실제 카운터를 자동으로 시작하지 않는다. 초기화 후 사용자 코드 영역에서 시작해야 한다.

```c
MX_GPIO_Init();
MX_TIM1_Init();
MX_TIM2_Init();
MX_TIM3_Init();

/* USER CODE BEGIN 2 */
if (HAL_TIM_Encoder_Start(&htim2, TIM_CHANNEL_ALL) != HAL_OK)
{
    Error_Handler();
}

if (HAL_TIM_Encoder_Start(&htim3, TIM_CHANNEL_ALL) != HAL_OK)
{
    Error_Handler();
}

__HAL_TIM_SET_COUNTER(&htim2, 0);
__HAL_TIM_SET_COUNTER(&htim3, 0);
/* USER CODE END 2 */
```

`TIM_CHANNEL_ALL`은 엔코더 해석에 필요한 CH1과 CH2를 모두 활성화한다.

이번 시험에서는 인터럽트를 사용하지 않았다. 하드웨어 타이머가 계속 계산하고, CPU는 반복문에서 CNT 값을 읽기만 했다.

```c
while (1)
{
    motor1_count =
        (int32_t)__HAL_TIM_GET_COUNTER(&htim2);

    motor2_count =
        (int16_t)__HAL_TIM_GET_COUNTER(&htim3);

    HAL_Delay(10);
}
```

## 11. 이번에 실제로 확인한 결과

MDD10A의 수동 버튼을 사용해 PWM·DIR 제어선을 연결하지 않고 엔코더만 STM32에 연결했다.

| 버튼 | 확인 결과 |
| --- | --- |
| M1A | `motor1_count`만 한 방향으로 변화 |
| M1B | `motor1_count` 변화 방향 반전 |
| M2A | `motor2_count`만 한 방향으로 변화 |
| M2B | `motor2_count` 변화 방향 반전 |

확인된 사실:

- 두 엔코더의 3.3V 전원이 정상이다.
- Motor 1의 PA0/PA1와 TIM2 연결이 정상이다.
- Motor 2의 PA6/PA7와 TIM3 연결이 정상이다.
- A/B 위상으로 정방향과 역방향을 구분할 수 있다.
- 두 엔코더 카운터가 서로 섞이지 않는다.
- 최종 전진 방향의 부호는 차체 조립 후 정한다.

## 12. 다음 단계: 카운트에서 signed RPM 계산

RPM을 계산하려면 세 값이 필요하다.

```text
1. 일정 시간 동안 변한 카운트 Δcount
2. 샘플 시간 Δt
3. 출력축 한 바퀴당 카운트 수 CPR
```

공식:

```text
RPM = (Δcount / CPR) × (60 / Δt초)
```

예를 들어 100ms마다 계산한다면:

```text
Δt = 0.1초
RPM = Δcount × 600 / CPR
```

부호를 유지하면 다음처럼 사용할 수 있다.

```text
양수 RPM = 정방향
음수 RPM = 역방향
0 RPM    = 정지
```

### 오버플로를 고려한 변화량

TIM3은 16비트이므로 65535 다음에 0으로 돌아가고, 역방향에서는 0 다음에 65535로 돌아간다. 짧은 주기마다 읽어서 부호 있는 16비트 차이로 변환하면 래핑을 처리할 수 있다.

```c
uint16_t now_raw = (uint16_t)__HAL_TIM_GET_COUNTER(&htim3);
int16_t delta = (int16_t)(now_raw - previous_raw);
previous_raw = now_raw;
```

한 샘플 구간에서 실제 변화량이 32767카운트를 넘지 않아야 이 방식이 안전하다. 현재 모터 속도에서는 충분한 여유가 예상되지만 실제 CPR을 확인한 뒤 다시 계산해야 한다.

## 13. 설정값을 볼 때 자주 헷갈리는 부분

### `Prescaler = 0`은 정지가 아니다

실제 분주비는 `PSC + 1`이므로 1분주다.

### `Period = 4199`의 한 주기는 4199개가 아니다

0도 포함하므로 0~4199, 총 4200카운트다.

### PWM 20%는 12V를 항상 2.4V로 만드는 것이 아니다

모터에 배터리 전압을 빠르게 연결·차단하며 평균적인 에너지 전달량을 조절한다.

### `Direct`는 모터를 직접 구동한다는 뜻이 아니다

엔코더 입력 CH1/CH2가 각각 TI1/TI2에 직접 매핑된다는 뜻이다.

### `No division`은 신호가 없다는 뜻이 아니다

입력 에지를 건너뛰지 않고 전부 사용한다는 뜻이다.

### `Input Filter = 4`는 네 번 평균이라는 뜻이 아니다

필터 코드 4에 해당하는 샘플링 주파수와 연속 확인 횟수를 선택한다.

### 엔코더 시험과 모터 제어 시험은 연결이 다르다

- MDD10A 수동 버튼으로 돌리는 엔코더 시험: STM32에는 엔코더선만 연결 가능
- STM32 PWM/DIR 자동 제어: MDD10A GND와 STM32 GND를 연결하고 PWM/DIR도 연결

## 14. 하드웨어 안전과 이번 사고에서 배운 점

- 전압 측정은 멀티미터 `COM`, `VΩ`, DCV 모드에서 전원 양단에 병렬로 한다.
- 전원이 들어온 개방형 PCB 위에서 탐침을 이동하지 않는다.
- 전원을 끈 상태에서 측정 집게를 먼저 고정하고, 측정 후에는 배터리를 먼저 분리한다.
- 탐침의 노출 금속이 PCB의 두 지점을 동시에 건드리면 멀티미터의 높은 입력저항과 관계없이 두 지점이 직접 단락될 수 있다.
- MDD10A는 절연 바닥과 나일론 스탠드오프에 고정하고 환기형 보호 덮개를 사용한다.
- 배터리 가까이에 15A 퓨즈를 유지한다.
- 퓨즈는 배선과 화재 위험을 줄이지만 반도체를 모든 순간 단락에서 보호하지는 못한다.
- 저항·도통 측정은 반드시 배터리와 모든 전원을 분리한 상태에서 한다.
