# 2026-10-16 공부 기록

## 학습 주제

STM32 기반 로봇 바퀴 제어의 학습 목표와 진행 순서를 정리합니다.
최종 목표는 ROS2의 주행 명령을 받아, 엔코더 피드백으로 좌우 바퀴 속도를 제어하는 것입니다.
모터를 정해진 시간 동안 돌리는 것은 작동 확인용 시험이며 최종 제어 방식은 아닙니다.

## 핵심 개념

### STM32와 ROS2의 역할

| 담당 | 역할 |
| --- | --- |
| Jetson / ROS2 | 센서 통합, 위치 추정, 경로 계획, 장애물 회피, 목표 전진·회전 속도 결정 |
| STM32 | 엔코더 측정, 바퀴 속도 계산, 목표 속도에 맞춘 PWM·DIR 출력, 명령 시간 초과 및 오류 대응 |
| 모터 드라이버 | STM32의 PWM·DIR 신호에 따라 모터 전력 구동 |
| 엔코더 | 실제 축 회전에 따른 A/B 신호 출력 |

좌우 목표 속도 변환과 오도메트리 계산을 어느 장치에서 수행할지는 통신 구조를 정할 때 확정합니다.

제어 흐름:

~~~text
ROS2 주행 명령
→ 좌우 목표 속도
→ STM32가 엔코더로 실제 속도 측정
→ 목표와 측정값 비교
→ 각 모터 PWM 조절
→ 다음 측정에서 결과 확인
~~~

### 엔코더의 의미

- 엔코더는 각도나 RPM 숫자를 보내는 장치가 아니라 회전에 따라 A/B 신호가 변하는 장치입니다.
- 현재 TIM2·TIM3의 Encoder TI12 모드는 A/B의 상승·하강 변화를 세는 ×4 방식입니다.
- A/B 한 주기에 4count이며, 실측한 한 바퀴당 count에 다시 4를 곱하지 않습니다.
- CNT는 신호 변화에 따라 하드웨어에서 계속 증가·감소합니다.
- 현재 프로젝트에서 메인은 약 10ms마다 CNT를 읽습니다. 메인 전체의 반복 주기가 10ms라는 뜻은 아닙니다.
- Encoder Mode에서 ARR은 카운터 최대값입니다. 내부 84MHz를 PSC·ARR로 나눈 값을 엔코더 카운트 주파수로 해석하지 않습니다.
- 엔코더 신호 주파수는 실제 회전 속도에 따라 달라집니다. 모터 PWM 주파수 20kHz와 별개입니다.

## 실습과 결과

### 현재 구성과 측정 기준

| 항목 | 값 / 상태 |
| --- | --- |
| MCU | STM32F446RE |
| 드라이버 | MDD10A |
| 주 실습 프로젝트 | STM32CubeIDE/workspace_2.2.0/446re_sample_project |
| 모터1 PWM / DIR | PA8 TIM1_CH1 / PC0 |
| 모터2 PWM / DIR | PA9 TIM1_CH2 / PC1 |
| 모터1 엔코더 | PA0·PA1 / TIM2, 32비트 |
| 모터2 엔코더 | PA6·PA7 / TIM3, 16비트 |
| 바퀴 지름 | 110mm, 우선 ±1mm 오차는 무시 |
| 바퀴 둘레 | π × 110 ≈ 345.6mm |
| 모터1: 5바퀴 count 변화량 | 12326 → 약 2465.2count/바퀴 |
| 모터2: 5바퀴 count 변화량 | 12378 → 약 2475.6count/바퀴 |

한 바퀴당 값은 사용자가 손으로 5바퀴 돌려 측정한 기준입니다.
제품 사양의 확정값이나 좌우 엔코더 구조가 다르다는 증거는 아닙니다.
최종 하중과 타이어 상태에서 실제 이동 거리와 비교하여 보정할 수 있습니다.

### 다음 실습: count를 회전량과 거리로 바꾸기

~~~text
count 변화량 = 현재 count − 기준 count
회전량(바퀴) = count 변화량 ÷ 한 바퀴당 count
바퀴 기준 거리(mm) = 회전량 × 345.6

이후 속도 단계:
속도(mm/s) = 구간 거리(mm) ÷ 실제 측정 시간(s)
RPM = 구간 회전량 × 60 ÷ 실제 측정 시간(s)
~~~

TIM3는 16비트이므로 경계를 통과할 때 단순 signed 누적값 차분으로 잘못 계산하지 않도록 처리해야 합니다.
현재 표시용 count는 무제한 누적 이동량이 아닙니다.

## 의문과 어려웠던 점

- ×4 카운트와 메인의 10ms 읽기 주기는 서로 다른 개념입니다.
- 같은 PWM을 줘도 실제 속도가 같다고 보장되지 않습니다.
- 엔코더로 구한 거리는 바퀴 회전 기준입니다. 헛돌거나 옆으로 미끄러지면 차체 실제 이동과 달라집니다.
- 타이어에 테이프를 감은 뒤 회전 저항은 줄었다고 관찰했으나 전진 미끄러짐도 있습니다.
- 최종 하중에서 접지력·회전 저항을 다시 확인해야 합니다. 무거워지면 필요한 구동 토크도 커집니다.
- 현재 3초 회전 시험은 최종 로봇 속도·회전 제어를 대신하지 않습니다.

## 복습할 내용과 학습 원칙

- 매 학습에서 로봇 제어에 어떻게 연결되는지 먼저 짚습니다.
- 초기화 → 측정 시작 → 기준 저장 → 주기적인 계산 → 구동 명령 적용 순서를 설명합니다.
- 인터럽트에서는 필요한 데이터 저장과 처리 요청을 우선하고, 계산·제어는 메인에서 수행합니다.
- 엔코더 CNT는 하드웨어가 직접 세므로 매 count마다 인터럽트가 필요한 것은 아닙니다.
- 예외적으로 인터럽트 안에서 처리가 필요한 경우에는 이유를 설명합니다.
- 코드 구조가 목적에 맞지 않으면 바로 이유와 함께 피드백합니다.
- 부가 학습은 [추가 학습 주제](stm32-timer-pwm/follow-up-topics.md)에 별도로 기록하고 본 순서를 확장하지 않습니다.
- 최종 정지·통신 오류 대응은 로봇 통합 시 함께 검증합니다. 워치독 등 추가 기능은 필요 시 기존 단계 안에서 다룹니다.
