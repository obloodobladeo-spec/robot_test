# encoder_basic 진행 정리 — 2026-11-12

## 현재 적용된 기본 코드

- 프로젝트: learning/stm32/encoder_basic.
- 모터1 CPR 2473.6, 모터2 CPR 2464.5. 각각 10회전 카운트 24736 및 (24666−21)로 계산했습니다.
- 바퀴 명목 지름 110mm, 코드 둘레 345.6mm, 구동 바퀴 중심 간격 234mm.
- 둘레는 최종 하중에서 실측 보정된 구름 둘레가 아닙니다.
- 현재 기본 프로젝트 PI 초기값은 Kp=0.15, Ki=0.15입니다. 다른 시험에서 사용한 값과 구분합니다.
- 기본 프로젝트에 HSE 변경이나 출발 보상, IMU 드라이버를 추가하지 않았습니다.
- 기존 UART 속도 명령, 엔코더 측정, PI, 오도메트리 및 ROS 연결 구조를 유지합니다.

## 모터 흔들림 검토

출발 떨림과 주행 중 방향 변화의 원인은 아직 확정하지 않았습니다. 게인만의 문제 또는 캐스터만의 문제로 단정하지 않습니다.
이전 고정 듀티 시험에서는 바퀴를 띄웠을 때보다 바닥에서 속도 변동이 컸지만, 이후 캐스터 구성이 변경되었으므로 현재 상태에 그대로 적용할 수 없습니다.
100ms 측정과 현재 둘레·CPR에서는 1카운트가 약 1.4mm/s에 해당합니다. 큰 물리적 흔들림을 이 양자화만으로 설명할 수는 없습니다.

## IMU 학습 계획 — 아직 구현·배선 검증 전

로봇이 없는 동안 STM32와 IMU만으로 학습합니다. 코드는 사용자가 직접 작성하고 설명·검토를 받는 방식입니다.
모듈은 TENSTAR GY-BNO085이며, 사진의 뒷면에 VCC_3V3가 표시되어 있습니다.
BNO085는 내부 자세 계산 기능이 있으며 SHTP 패킷으로 보고서를 주고받습니다.
I²C를 우선 선택했습니다. UART-RVC는 출력 항목이 제한되고, UART-SHTP는 3Mbps 및 센서 외부 클럭 조건을 고려해야 합니다.

| 용도 | 예정 STM32 핀 | 설정 |
|---|---|---|
| SCL | PB8 | I²C1 |
| SDA | PB9 | I²C1 |
| INT | PC4 | 입력, 데이터 준비 확인 |
| RST | PC5 | 출력, 센서 재시작 |
| 전원 | 3V3 / GND | 공통 전원·접지 |

현재 확인한 기존 모터·엔코더·UART 핀과 충돌하지 않는 계획입니다. CubeMX 반영이나 실물 통신 검증은 아직 하지 않았습니다.
I²C 모드 계획은 PS0/PS1 LOW, AD0 LOW(7비트 주소 0x4A), CS HIGH입니다. 모듈 내 저항·점퍼 상태는 실물에서 확인해야 합니다.
RST는 코드에서 센서를 재시작하기 위한 선택 연결입니다. INT는 준비되지 않은 센서를 계속 읽지 않도록 사용합니다.
I²C 대기로 기존 PI 제어가 밀리지 않게 대기 시간을 제한해야 합니다. DMA는 첫 통신 학습에는 추가하지 않고 필요성을 측정한 뒤 판단합니다.

학습 순서: 배선 확인 → CubeMX I²C/GPIO 설정 → 초기화·제품 ID 응답 → 가속도·각속도·자세 읽기 → 모터 제어와 동시 실행 검증 → ROS IMU 전달 → 융합 학습.

- [BNO08X 공식 데이터시트](https://www.ceva-ip.com/wp-content/uploads/BNO080_085-Datasheet.pdf)

## 이번 업로드 범위와 검증

encoder_basic 소스와 ROS scan_reader 및 sensor_msgs 의존성을 동기화했습니다. scan_reader는 현재 +90도 거리 읽기, 범위·유효값 확인 및 로그 주기 제한을 사용합니다.
사용자 요청에 따라 encorder_test 변경과 테스트 파일은 이번 커밋에서 제외합니다.
이번 작업은 기록·소스 동기화이며 새 제어 기능을 작성하거나 보드 다운로드·모터 구동을 하지 않았습니다.
기존 빌드 결과물과 SOURCE_SNAPSHOT/SHA256SUMS는 이전 스냅샷 기준이며 이번 소스의 새 빌드 결과를 뜻하지 않습니다.
