# 학습 보관본 검증

검증일: 2026-10-29. 소스의 동작 수정이 아니라 학습 기록과 파일을 보관하는 작업입니다.

## 이번 업로드에서 확인한 것

- 복사한 원본 파일945개를 원본 경로의 파일과 바이트 단위로 비교해 일치했습니다. 출처·파일 수는 SOURCE_SNAPSHOT.json, SHA-256은 SHA256SUMS.txt에 있습니다. 새 문서와 출처 목록은 이945개와 별도입니다.
- 학생 작성 ROS 패키지의 Python 파일8개를 AST로 검사해 문법이 통과했습니다. SDK의 외부 Python 도구 전체가 현재 Python에서 실행된다는 뜻은 아닙니다.
- URDF와 세 package.xml의 XML을 파싱했습니다. URDF 링크7개·joint6개의 부모/자식 이름, 단일 루트와 자식 중복 여부를 확인했습니다.
- 보관본 ROS 패키지3개를 WSL Humble에서 별도 임시 build/install 경로로 새로 빌드했습니다. `motor_bridge`, `robot_description`, `sllidar_ros2` 모두 완료됐습니다.
- C1 SDK는 기존 로그와 같은 계열의 컴파일 경고가 있으며 실패가 아닙니다. 경고를 없애기 위한 임의 소스 수정은 하지 않았습니다.
- 새 보관본에서5MiB를 초과하는 개별 파일은 없었습니다. 중첩 Git·IDE 캐시·Python 캐시는 제외했습니다.
- 기존 독립 시험 패키지의 `python -m unittest discover -s tests -v` 회귀 검사21개가 통과했습니다. 이 결과를 새 학습 브리지의 안전 기능 검증으로 해석하지 않습니다.

```text

Summary: 3 packages finished [37.2s]
1 package had stderr output: sllidar_ros2
```

## 이전 실습에서 확인한 것

- STM32 개별 모터·엔코더·속도 제어·통신·바퀴 오도메트리와 ROS 토픽/TF 실습. 상세 조건은 날짜별 노트와 motor_tests 자료를 따릅니다.
- URDF 전체 모델과 launch, 저장한 RViz 설정 표시.
- TF base_link→laser=[0.150,0,0.088]m, 학습용1m 이동을 합친 odom→laser=[1.150,0,0.088]m.
- 실제 C1 health=OK, 약10Hz·720개 거리값 수신. 독립20초 검사에서는174개·약10.19Hz, 최대 간격약0.1315초를 확인했습니다.
- scan_reader 실제 수신 로그 확인 사례가 있습니다. 다만 보조 조회 이후 다른 조회가 되는 등 간헐적 발견 문제를 해결한 것은 아닙니다.
- 마지막에 제조사 드라이버의 정상 종료를 통해 Stop motor 로그·종료코드0을 확인하고 사용자가 물리적 정지를 확인했습니다.

## 이번 작업에서 실행하지 않은 것과 남은 한계

- 새 펌웨어 빌드·플래시·실제 모터 구동·C1 재구동은 이번 업로드 검증에서 하지 않았습니다. 원본 STM32 프로젝트는 별도 IDE·툴체인에서 재빌드해야 합니다.
- 새 Jetson 설치나 전체 신규 Ubuntu 환경의 apt·rosdep 설치를 다시 시험하지 않았습니다. 코드에 빠진 일부 의존성 선언은 README의 명시 설치 명령으로 안내했습니다.
- WSL DDS/CLI 발견 문제는 미해결입니다. no-daemon, spin-time5, 로컬 통신 설정의 단발성 성공을 완전한 해결로 기록하지 않습니다.
- 라이다의 실제 차체 장착 방향·거리 정밀도·연속 운전·모터 최종 하중 안정성을 이번에 새로 검증하지 않았습니다.
- IMU·EKF·SLAM·Nav2와 통합 bringup은 아직 계획입니다. Gazebo를 완료된 학습으로 포함하지 않습니다.

전체 노트의 과거 실험과 현재 코드 설정은 구분합니다. 오래된 프로젝트를 그대로 실제 로봇에 업로드하면 마지막 저장된 시험 동작이 실행될 수 있으므로 프로젝트의 main과 실습 목적을 먼저 확인합니다.
