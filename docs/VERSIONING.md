# 브랜치·버전 관리 규칙

## 브랜치

| 브랜치 | 용도 | 규칙 |
|---|---|---|
| `main` | 검증을 마친 기준 상태 | 직접 실험 코드를 올리지 않는다. 테스트 브랜치에서 실기 검증 후 병합 |
| `test/<주제>` | 실기 시험·튜닝 중인 작업 (예: `test/imu-drive-tuning`) | 시험 로그·중간 결과를 함께 커밋. 값이 바뀔 수 있음 |
| `feature/<주제>` | 아직 실기 시험 전인 새 기능 | 빌드·정적 검사까지 통과 후 test 브랜치로 |

## 버전 (태그)

`vMAJOR.MINOR.PATCH`

- **MAJOR**: 직렬 프로토콜(`V=… W=…`, telemetry 형식) 같은 호환이 깨지는 변경
- **MINOR**: main에 병합된 기능·하드웨어 단계 (예: IMU 통합, EKF, SLAM)
- **PATCH**: 문서·링크 수정, 값 미세 조정

태그는 main 커밋에만 붙인다. 테스트 브랜치의 중간 상태는 태그 대신 브랜치 이름과 CHANGELOG의 `Unreleased`로 구분한다.

## 변경 기록

모든 변경은 루트의 [CHANGELOG.md](../CHANGELOG.md)에 적는다. 펌웨어·ROS 파라미터 값을 바꾸면 값, 근거(시험 이름·날짜), 이전 값을 함께 적는다.
